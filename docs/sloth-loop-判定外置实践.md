# sloth-loop 判定外置实践（Task 接入补充规范）

> 状态：**指南 / 规范（文档）** —— 面向「用 sloth-loop 跑一个新任务」的接入者，不含引擎代码。
> 目标：把「什么算对」写进**脚本**，让判定可复算、可自动沉淀，而不是跑完让 LLM 事后解释。
> 关联：`README.md`「通用接入契约」、`docs/sloth-loop-USAGE.md`、
> `docs/sloth-loop-AI-TEAM-AND-SELF-EVOLUTION.md`、`docs/LOOP-ESSENCE-AND-LEARNINGS.md`。

## 0. 一句话

判定是**输入的一等公民**：`success_criteria`（判定式）+ `wrapper`（把判据写进脚本、纯计算）。
「跑完让 LLM 说好不好」不是判定，是解释 —— **不算数**。

## 1. 三件套里「判定」在哪

| 输入件 | 含义 | 判定的角色 |
|---|---|---|
| `signals` | 一批候选做法 | 被判定对象 |
| `success_criteria` | `metric + operator + threshold`（如 `win_rate >= 0.35`） | **判定式**：什么算对 |
| `wrapper` | 把信号变成可测结果的一段脚本（纯计算、不调 LLM） | **判定执行者**：把结果算成 PASS / FAIL |

## 2. 真值表（ITEM-TRUTH-TABLE）—— 把「什么算对」写死

每一行 = 一条**可自动判定**的断言；「不命中」也要写成显式期望（防止只测正例）。

| 字段 | 含义 |
|---|---|
| `id` | 断言标识 |
| 输入 / 环境构造 | 这一行在什么条件下成立 |
| 期望结果 | 命中 / 不命中 / N-A（三选一，必须显式） |
| 期望关键字 | 结果里必须出现（或不出现）的关键字 |
| 判定式 | 机器可计算的判定（可引用 `success_criteria`） |
| 状态 | 待建 / 已建 / 已知缺口 |

## 3. judge 脚本契约

- 输入：真值表 + 实跑结果；输出：**`PASS` / `FAIL` / `UNKNOWN`**（不允许「大概对」）。
- **纯计算、不调 LLM**（判定权外置的核心）。
- `UNKNOWN` 必须 **fail-closed** 或显式升级，**不得静默当作 PASS**。
- 退出码与门禁对齐：`0` = PASS；非 `0` = FAIL / UNKNOWN。

## 4. 复算与破框（可信性承重件）

- **三轮一致**：同一输入连跑 3 次，结果与关键字**逐字节一致**（排除随机性与一次性巧合）。
- **破框复验**：换输入域 / 换**独立的第二条取证路径**重算，结论必须不变
  —— 任何**不可逆裁决**（删改 / 覆盖 / 发布）之前尤其必须做。单维度取证就下结论 = 不可信。

## 5. 沉淀（闭环）

- 未达标 → 自动写**失败模式库**（Pattern 默认证据；**status 变更仍需人工审批**）。
- 达标 → 复用为**优先信号**。
- 这一步让「踩坑」从手工记录变成流程副产品。

## 6. 反模式（不要这样）

- 判定写在 prose prompt 里（靠自觉）；
- 只写正例、不写「不命中」的期望；
- **单维度取证**就下不可逆结论；
- 把 `UNKNOWN` 当 `PASS`；
- 用 LLM 的「我觉得可以」替代判定式。

## 7. 与「AI Team / 蜂群」的关系

判定外置是角色分离的**前置**：先有真值表 + judge 脚本（判定权外置），才轮到多角色。
顺序反了，团队只会把「一个 LLM 打转」放大成「N 个 LLM 互相点赞」
（详见 `docs/sloth-loop-AI-TEAM-AND-SELF-EVOLUTION.md`）。

---
*本文只讲「怎么把判定写进脚本」这一条可复用做法；不引入任何 LLM，也不改变引擎的零 LLM 边界。*
