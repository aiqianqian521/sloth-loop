## 1. 既定模式（工程侧，sloth-loop 本体）

### 1.1 一句话定义
**接→化→发（p9） + OODA 严格模式 + 三轮评估（md5 一致） + 破框复验。**

出处：`docs/sloth-loop-0927-regression-and-fixes-2026-09-28.md`（"采用既定模式：接→化→发（p9）+ ooda + 三轮评估 + 破框复验"）、`docs/LOOP-ESSENCE-AND-LEARNINGS.md §5`。

### 1.2 四段
1. **接→化→发（p9）**
   - 接：接收任务/问题，先想明白根本目标、产出该放哪、怎么算"做完"（LOOP-ESSENCE §2 工作哲学）。
   - 化：把问题**转化为可复用流程/判据**（不是一次性报告）——落方案、落 config 判据。
   - 发：执行并**沉淀**（教训库 + 偏差模式库 + 矫正规则库）。
2. **OODA 严格模式**（= sloth_engine 7 步 / 外部 OODA skill）
   - Understand → Observe → Orient → Decide → Act → Verify → Learn。
   - 硬门：**Observe 必先读真实文件锚核现状，禁凭上下文印象判断**（LOOP-ESSENCE 规则9）。
   - 代码落点：`sloth_engine/ooda_pipeline.py`；Agent 层由外部 OODA skill 补充（见 ooda_pipeline.py 注释）。
3. **三轮评估**（确定性）
   - 同一任务跑 **3 遍**，指标/产物**逐字节一致（md5 一致）**才算通过。
   - 出处：`ONBOARDING.md §八`；命令：`orchestrator.py --once` × 3。
4. **破框复验**（换维度重验）
   - 换**币种/周期/剔参数/换独立实现**重跑，确认结论不是"拟合单一样本"。
   - 出处：`<KB_ROOT>/PM既定流程-7步评估与loop挂载-RUNBOOK.md` 第7步；regression 记录"破框：mock/doctor/once 端到端无未来数据红线"。

### 1.3 验收标志（缺一不合格）
- [ ] 方案/判据**已落盘**（loop 不会凭空记住方案）。
- [ ] OODA 每步**留痕**（`work_ooda/`）。
- [ ] **三轮 md5 一致**。
- [ ] **破框**换维度重验通过。
- [ ] 教训/对错清单**回抽** `LOOP-ESSENCE-AND-LEARNINGS.md §3`。

## 2. 既定流程 7 步（PM 侧，业务任务）

出处：`<KB_ROOT>/09_可复用流程\05-loop与工程流程\PM既定流程-7步评估与loop挂载-RUNBOOK.md`。

1. **先列出修复/验证方案**（落盘 `projects/<domain>/<task>/RULEBOOK.md`，loop 只读预写）。
2. **用 p9 + 蜂群评估方案有效性**（agent/人工先行，非 loop 内置）。
3. **用 p9 + 蜂群提出 3-5 个致命问题场景**（翻译成 config `judge_criteria` 喂给 loop）。
4. **用 OODA 严格模式修复**（wrapper 实现修复逻辑）。
5. **完整走 3 遍评估**（`orchestrator --once` × 3，evidence md5 一致）。
6. **OODA 严格模式确认改造完成 + 全文件检查**（README/skill/引擎一致性巡检）。
7. **最后用破框方法论重新验证完整流程**（换币种/周期/剔参数重验）。

### 2.1 sloth-loop 内容 ↔ 7 步映射（关键认知）
| 7步 | sloth-loop 载体 | 一致性 |
|---|---|---|
| 1 方案 | `config.yaml` + RULEBOOK | ✅ 对齐（方案须落盘） |
| 2 p9+蜂群评估 | 架构师skill + 蜂群子代理 | ⚠️ 半对齐（agent/人工动作） |
| 3 致命场景 | runbook 场景 → `judge_criteria` | ⚠️ 半对齐（须翻译成判据） |
| 4 ooda 修复 | `ooda_pipeline` + `self_modify_gate` | ✅ 对齐 |
| 5 3 遍评估 | `ONBOARDING §八`（3 遍一致 md5） | ✅ 对齐 |
| 6 确认+全文件 | `verifier` + agent/人工巡检 | ⚠️ 部分（须单独巡检） |
| 7 破框 | 换币种/周期/剔参数 | ✅ 对齐 |

### 2.2 三条防走偏铁律
1. **loop 是编排器，不是计算器/评估器**：p9/蜂群评估、致命场景设计、全文件检查是 **agent/人工先行**，结论写进 config+runbook 判据，loop 才执行/验证。
2. **不要把通用 OODA skill 状态栏当整体流程**：OODA 严格模式只是既定流程的第 4、6 步。
3. **"列出修复方案"必须落盘**。

## 3. 大任务循环（GRAND-LOOP，长期自进化闭环）

> 完整定义见同目录 `2026-09-05-grand-loop-task.md`（指导文件，静态）与 `2026-09-05-grand-loop-status.md`（动态 registry）。
> 触发口令：**"开始执行sloth-loop自进化和蒸馏大厂项目"**。

### 3.1 大循环 A→B→C→D（永不停止的回环）
- **A 蒸馏大厂 + loop 代码自进化**：A1 扫描 → A2 蒸馏（file:行段证据）→ A3 V1/V2/V3 + D7 反向 → A4 改 loop 代码 adopted 回填（契约不变量+跑绿+gate）→ A5 全量落盘 + 蜂群深化 → A6 提交 → A7 判"蒸馏流程无误?"（否→回 A1 / 是→进 B）。
- **B 用蒸馏实测真值修正 architect-skills**（按 Russell 周期重封存落盘：`output/{project}/{date}/report.md` + golden 行 + `docs/iteration-tracker/{project}-{date}.md`，非在线 append）。
- **C 用修正后 architect-skills（16 维）评估 sloth-loop + 蜂群** → 覆盖矩阵 + 缺口 + 风险分级 → 修正（adopted 回填 + pytest + gate）。
- **D 把 A+B+C 梳理为"整个大任务"清单**（动态维护）+ 执行中持续完善 + 回环 A→B→C→D→完善→回 A。

### 3.2 四步执行流程（§5，用户确认前禁动手）
- **步骤 A 收集/学习**：读指导文件 + 权威记忆 + 核对 4 根路径存在（Test-Path）+ 确认基线。
- **步骤 B 复述理解**：用自己的话完整复述大循环 A/B/C/D + 断言表 + 任务边界 → 存档 `work_ooda/{date}-grand-loop/`。
- **步骤 C 确认范围**：把理解列给用户，**等确认后**才执行。
- **步骤 D 执行并记录**：按 A→B→C→D 回环执行，每 OODA 轮 `work_ooda` 留痕；遇阻碍**立即停 + 上报，禁绕过**。

### 3.3 强制纪律（§0.1，继承 v7 #1-#14 + 蒸馏 D1-D13）
禁跳步 / 禁乱执行 / 禁只做部分 / 禁改判 / **禁编造证据（证据须真实 file:行段可回溯）** / 遇阻立即停+上报禁绕过 / 唯一例外=用户确认调整 / 伴生函数覆盖 / 诱因真实构造 / 分支全覆盖 / 三栏并存（_INDEX 验证状态 + 计数 + 去重）/ 打包清理命名规范 / 任务边界强制声明 / 禁擅自新增模板未要求文件 / 记录完整性。

### 3.4 判定（§7，写死真值）
| 判据 | 场景 | 期望真值 |
|---|---|---|
| GL-A7 | 蒸馏流程无误 | distillation-flow-diagram open audit 全清零 + 流程自洽 |
| GL-B | architect-skills 修正 | Russell 周期重封存落盘；实测真值校正检查点 |
| GL-C | 评估+修正 sloth-loop/蜂群 | 16 维覆盖矩阵 + 缺口 + 风险分级；adopted 回填跑绿 + gate PASS + commit |
| GL-D | 大任务清单维护 | 动态清单 + commit 链 + OODA 每细节跟进 |
| GL-adopted | 每条 adopted 回填 | 契约不变量 xfail→passed + 全量回归无回归 + gate PASS + commit |

### 3.5 交付物（§8，每轮缺一不合格）
1. commit（docs-only → gate SKIP；代码改 → gate 必过 + pytest 无回归）。
2. `_INDEX` / iteration-tracker 更新。
3. `work_ooda` OODA 轮次留痕。
4. **`ISSUES.md` + `AGENT_ERROR_LOG.md` 等价声明每轮必落**（全通过也写"无遗留/无执行错误"）。
> 硬映射：RECORD 声称数 == evidence 实际数（N==M）才允许提交。

### 3.6 通用闭环条款 G-1~G-9
G-1 修复前复现 / G-2 伴生函数覆盖 / G-3 诱因真实构造 / G-4 分支全覆盖 / G-5 三栏并存 / G-6 命名清理规范 / G-7 交付缺一不合格 / G-8 编译判据独立证据+正确解释器 / G-9 判据-证据硬映射。

## 4. 怎么落地到 sloth-loop（OODA 对应）
- Understand = 先想明白根本目标/放哪/怎么算完。
- Orient = 看现状（先看真实数据，禁凭印象）。
- Decide = 定可复用 SOP + task（config 只换输入）。
- Act = 跑（经 orchestrator，禁手算领域数据）。
- Verify = 对账核验（人标对错 + 看结果合格没）。
- Learn = 遇错总结 → 追加教训库 + 偏差模式库/矫正规则库。
